# 2026年11月14・15日 JRA 8頭立て複勝6頭買い検証

2026年1〜10月のJRA 8頭立て107レースを使った検証結果は [BACKTEST.md](BACKTEST.md) を参照。高オッズ6頭・逆数配分は全レースで1頭以上的中したが、実払戻ベースの回収率は77.2%だった。アプリの「過去検証」にも集計とレース別実績を表示する。

出走馬の過去成績と騎手の前年成績を加えた再検証は [RUNNER_STUDY.md](RUNNER_STUDY.md) を参照。取得できた84レースでは、馬・騎手情報で6頭を選んでも後半の検証は赤字だった。

## アプリを動かす

```bash
npm install
npm start
```

ブラウザで `http://127.0.0.1:3000` を開く。Node.js 20以上を想定。公開日の8頭立てレースをJRA出馬表から検索し、レースを選ぶと馬名と単勝・複勝オッズを読み込む。JRAページのHTML構造に依存するため、構造変更時は取得処理の更新が必要になる。対象日の出馬表が公開される前は結果が空になる。手入力でも計算できる。

参考画像に合わせ、買わない2頭の初期案は**複勝オッズ下限が低い2頭**（高オッズの6頭を購入）。複勝オッズが未掲載の場合だけ単勝オッズを仮の選定基準に使い、購入配分は複勝オッズが揃うまで行わない。購入比率は、選んだ6頭の複勝オッズ下限の逆数に比例させ、100円単位で1頭だけ的中した場合の想定払戻をならす。予算1万円で12・12・6・6・4・4倍の6頭を買う例では、配分は900・900・1,700・1,700・2,400・2,400円となり、下限オッズ固定での1頭的中時の最悪損失は400円（等額配分では3,600円）。これは画像の考え方を再現する**仮想例**であり、実際のJRAオッズを示すものではない。

「3着内推定が高い6頭」への切り替えも可能。この推定は単勝オッズから作る市場ベースの順位モデルで、独立した予測や利益の根拠ではない。画像の37.5%は8頭の実力が同じという仮定での3/8であり、実際の各馬に一律には当てはめない。チェック欄とオッズを変更すると56通りの損益を再計算し、等額配分と逆数配分の1頭的中時の損益を比較する。

購入案はブラウザのローカルストレージに保存する。確定後に実際の払戻額と返還額を入力すると、確定収支と合計収支を表示する。JSON書き出しと読み込みでバックアップ・移行できる。ブラウザ間の自動同期はない。

### 任意のAI分析

ルートに `.env.local` を作り、次のように指定してサーバーを再起動する。キーはブラウザのローカルストレージには保存せず、サーバー側からOpenAI Responses APIに送る。

```text
OPENAI_API_KEY=ここにAPIキー
OPENAI_MODEL=gpt-4.1-mini
```

キーがない場合もレース検索、配分、記録は動く。AIは取得した近走データの補助的な文章分析だけに使い、確率や購入額は変更しない。APIへの送信内容は選択したレースの公開データ。AI機能は実キーが未設定のため、接続動作は未検証。

## 目的と予算

- 対象は11月14日（土）・15日（日）の東京、京都、福島で、**馬券発売開始時に8頭立て**のレース。
- 1レースだけを選び、複勝を6頭に各100円以上、100円単位で購入する。**購入総額は最大10,000円**。両日を通じて追加購入はしない。
- 2頭は購入しない。通常の3着までの決着なら、6頭のうち少なくとも1頭が的中する。ただし、的中と黒字は別。
- 予想収支に根拠がない場合や、条件に合うレースがない場合は購入を見送る。予算は使い切る必要がない。

## 日程と判定

| 時点（日本時間） | 作業 |
| --- | --- |
| 11月12日（木）16時過ぎ | 馬番なしの出馬表から、両日の8頭立て候補を拾う。エリザベス女王杯など一部GIは発表時刻が異なる。 |
| 11月13日（金）10時過ぎ | 14日分の馬番入り出馬表を確認する。 |
| 11月14日（土）10時過ぎ | 15日分の馬番入り出馬表を確認する。 |
| 各候補の発走前 | 発売開始時頭数、取消・除外、馬場、馬体重、騎手変更、複勝オッズを再確認し、購入するなら締切に余裕を持って確定する。 |
| レース確定後 | 実際の払戻金・返還金から収支を記録する。 |

馬番入り出馬表の発表時刻は通常のレースの場合。GIや一部重賞はJRAの個別案内を優先する。

## 6頭の選び方

1. JRA出馬表に記載された8頭から候補レースを列挙する。頭数だけで決めず、近走、距離・コース、馬場、枠順、騎手、休養、馬体重を記録する。
2. 各馬の3着以内に入る確率を、**オッズとは別の根拠**で推定する。根拠のない数値は「期待値」と呼ばない。
3. 8頭から見送る2頭を選ぶ。各組合せについて、残り6頭の複勝オッズの下限と、少なくとも1頭だけが的中する場合の損失を比較する。単純に人気下位2頭を外すと、残る6頭の払戻が低くなりやすいので、払い戻しも見る。
4. プラスの期待収支を独立した確率推定で示せないときは、損益シナリオを「参考値」として示し、購入を見送る判断を基本とする。

## 金額配分と損益計算

- 購入する6頭への金額を `s1 ... s6` 円、合計を `S ≤ 10,000円` とする。各金額は100円以上、100円単位。
- 各馬の複勝オッズの**表示下限**を `l_i`、上限を `u_i` とする。配分案は、どの1頭だけが当たっても払戻が近くなるよう `s_i × l_i` をそろえる案を基準にし、100円単位へ丸める。これは損失をならす方法であり、期待利益を増やす保証はない。
- 8頭の1〜3着の組合せは `C(8,3) = 56` 通り。各組合せで、購入した馬の想定払戻 `Σ(s_i × l_i)` と想定収支 `払戻 − S` を計算する。上限 `u_i` を使った楽観ケースも併記する。オッズの単純な合算は概算であり、実際の払戻とは異なり得る。
- 56通りのうち、**最悪収支**、**1・2・3頭的中ごとの最悪収支**、黒字となる組合せ数を表示する。組合せ数を勝つ確率として扱わない。
- 独立した確率推定 `p_i` が用意できた場合だけ、概算期待収支 `Σ(s_i × p_i × 推定払戻倍率_i) − S` を算出する。確率、想定オッズ、推定方法、推定時刻を残す。購入でオッズが変化する点も考慮する。
- 購入後にオッズが動くので、下限での試算も最低払戻の保証ではない。購入前の試算と、確定払戻による実績を分けて記録する。

## 購入判断

次のいずれかなら見送る。

- 対象レースが8頭立てではない、または複勝の発売・払戻条件を確認できない。
- 出走取消・除外、馬場や騎手の変更があり、6頭と配分を再計算できない。
- 払戻下限での最悪損失が自分の許容額を超える。
- 確率推定に根拠がなく、利益が出るという判断を支えられない。
- 締切までに最新オッズと投票内容を確認できない。

購入する場合は、**レース名、購入する6頭の馬番・馬名、各購入額、合計、オッズ取得時刻、56通りの収支、見送る2頭、選定理由**を購入前に一覧にする。最終的な投票内容と締切時刻は利用する購入手段で確認する。
